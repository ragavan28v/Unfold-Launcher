Unfold — App Classification Seed
Database
Purpose:
 This document defines the initial app-classification
database and matching logic Unfold uses on first launch to
auto-sort a user's installed apps into folders. Paste this whole
document into the agentic builder as the spec for the "smart
folder seeding" module.
1. Design Principles
1. 
2. 
3. 
4. 
Never hardcode a lookup table as the only path.
 Use a
priority-ordered resolver (Section 4) so
unknown/regional/future apps still get classified.
Backend categories ≠
 
user-facing folders.
 Classify into the
full 36-category taxonomy internally, then collapse into ~10
15 folders for display (Section 3).
Package name is the primary key.
 App names
change/localize; package names don't.
Ship as data, not code.
 The database should live in a
JSON asset (or bundled Room-prepopulated DB) so it can
be updated without an app release.
5. 
Never block first launch on classification.
 Run seeding as
a background/async pass; show "Other" or "Unsorted"
immediately, then animate apps into folders as
classification completes.

Rule of thumb: if a user has fewer than ~3 apps in a merged
bucket, fold it into the nearest neighbor or into "Other" rather
than showing a near-empty folder.
4. Classification Resolver (priority order)
resolve(installedApp):
1. Exact package-name match in seed DB   
→ return category
2. Package-name PREFIX/regex rule match  
→ return category
(e.g. "com.supercell.*" → GAMES, 
"com.king.*" → GAMES,
"*.bank*"/"*.upi*" heuristics → 
FINANCE)
3. Play Store category metadata (if 
fetchable)    
→ map Play category → our 
taxonomy
4. App label keyword match (fallback)    
→ e.g. "bank", "pay", "wallet" → FINANCE;
"cam", "photo" → PHOTOGRAPHY
5. Unmatched                             
→ OTHER (user can manually re-sort;
log package name for future DB update)
Store each seed entry as:
{
}
"package": "com.instagram.android",
"appName": "Instagram",
"category": "SOCIAL",
"aliases": ["com.instagram.lite"]
Package-rule entries (regex, applied at step 2) as a separate
array:
{ "pattern": "^com\\.supercell\\.", 
"category": "GAMES" },
{ "pattern": "^com\\.king\\.", "category": 
"GAMES" },
{ "pattern": 
"^com\\.miHoYo\\.|^com\\.HoYoverse\\.", 
"category": "GAMES" },
{ "pattern": 
".*\\.bank.*|.*\\.upi.*|.*payzapp.*|.*imobi
le.*", "category": "FINANCE" },
{ "pattern": 
"^com\\.google\\.android\\.apps\\.docs.*", 
"category": "PRODUCTIVITY" }
Note: many 
packageName values above (esp. banking, OTT,
and regional apps) vary by publisher/region and should be
verified against the Play Store listing at build time or via a
periodic scraper
, not trusted blindly — mark these with
"verified": false in the JSON so the app can re
check them via PackageManager category metadata at runtime.
